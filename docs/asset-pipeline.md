# The asset pipeline

Four stages: **manifest → fetch → process → runtime**. Each one writes something
the next one reads, and every intermediate artefact is either committed (small,
textual, reviewable) or reproducible (large, binary, gitignored). Nothing binary
is ever committed — `npm run guard` enforces that.

```
tools/manifest/*.json          committed   what we want, and its provenance
        │  npm run assets:fetch
        ▼
assets/source/                 gitignored  content-addressed blobs, 1.65 GiB
assets/assets.lock.json        committed   sha256 + md5 of every file
        │  npm run assets:process
        ▼
public/assets/                 gitignored  KTX2 / GLB / SH9, three tiers
public/assets/assets.runtime.json          the index the game loads first
```

---

## Stage 1 — the manifest

Three committed JSON files declare every third-party asset:

| File                           | Entries        | Source files | Downloaded   |
| ------------------------------ | -------------- | ------------ | ------------ |
| `tools/manifest/textures.json` | 41 materials   | 117          | 1.149 GiB    |
| `tools/manifest/models.json`   | 39 models      | 255          | 0.436 GiB    |
| `tools/manifest/hdris.json`    | 4 environments | 4            | 0.067 GiB    |
| **Total**                      | **84**         | **376**      | **1.65 GiB** |

Each entry carries three separable things:

1. **Provenance** — provider, provider asset id, author, licence, source URL,
   and for every constituent file its exact download URL, provider-published
   md5, and byte count. None of this is guessed; it comes from
   `api.polyhaven.com/info/<id>`.
2. **Intent** — the stable runtime id (`mat.road.asphalt.worn`), tags, whether
   it preloads, the material spec that binds its textures.
3. **Build targets** — a per-tier ladder (see stage 3).

**One entry, many files.** A PBR material is three JPEGs; a Poly Haven model is a
`.gltf` plus a `.bin` plus a handful of textures. `files[]` lists every one with
its own md5, so a truncated download is caught per _file_ rather than per asset.

**Two entries download nothing.** `mat.glass.window` and `mat.road.markings` are
`provider: 'procedural'`: Poly Haven publishes neither window glass nor lane
markings (checked against all 849 of its texture ids), so both are generated by
the pipeline. They still get manifest entries, because consumers need a stable
id regardless of where the pixels came from.

**Characters are not in here.** `tools/manifest/characters.json` is written by
`tools/build-characters.ts` and describes fourteen generated characters. It
declares no provider, no files, and no downloads — see
[`../ATTRIBUTION.md`](../ATTRIBUTION.md), which verifies that mechanically.

### Why Poly Haven and not ambientCG

Both are CC0 and both are good. Poly Haven publishes a **per-file md5**;
ambientCG ships whole-material zips with no hash. With Poly Haven the integrity
chain runs from the provider's own published digest all the way to the byte on
disk. With a zip it would stop at the archive. That decided it.

## Stage 2 — fetch

`npm run assets:fetch` resolves every manifest entry, downloads what is missing,
and verifies what it gets.

- **Content-addressed store.** Blobs live at `assets/source/cas/<sha[0:2]>/<sha>`
  and the materialised tree is built from them. Two assets sharing a file store
  it once.
- **Verified on arrival.** Every download is checked against the manifest's md5
  and byte count before it is accepted. A mismatch is a hard failure, not a
  warning.
- **Warm re-runs are free.** A cached blob is confirmed by index lookup plus an
  mtime tripwire — a blob whose mtime moved is re-hashed rather than trusted.
- **Resumable.** Range requests, stall-aware timeouts, bounded retries.

It writes `assets/assets.lock.json`, which is **committed** and is the
reproducible-fetch contract: for all 376 files, the URL, provider md5, locally
computed sha256, byte count, owning entry, and destination path — plus a
per-entry digest computed over the sorted `"<sha256>  <path>"` lines, so it is
stable across fetch order and machine.

That lockfile is also the evidence base for the attribution audit: it records
what actually crossed the network. All 376 files came from exactly one host,
`dl.polyhaven.org`.

## Stage 3 — process

`npm run assets:process` turns verified source blobs into the GPU-native build.

### Three tiers

| Tier     | Textures           | Normals       | Models                                            |
| -------- | ------------------ | ------------- | ------------------------------------------------- |
| `mobile` | 1024 px, ETC1S q55 | 1024 px UASTC | 35 % triangles, Draco + meshopt, 12-bit positions |
| `high`   | 2048 px, UASTC q80 | 2048 px UASTC | 70 % triangles, Draco + meshopt, 14-bit           |
| `ultra`  | 4096 px, UASTC q95 | 2048 px UASTC | 100 % triangles, meshopt only                     |

All KTX2 containers get Zstandard supercompression at level 18.

### Codec choices, and why

- **Albedo → ETC1S.** A shared-palette codec on high-frequency colour is
  acceptable; the bandwidth saving is not.
- **Normals → UASTC, capped at 2K.** ETC1S mangles tangent vectors into blotchy,
  faceted lighting. UASTC is four times the bits and worth every one.
- **ARM (AO / roughness / metalness packed into R / G / B) → ETC1S.** Low
  frequency, low contrast, and read three times over: one texture serves
  `aoMap`, `roughnessMap` and `metalnessMap`, which is a 3× VRAM saving before
  compression even starts.

### Two deliberate deviations, both measured

**1. `--clevel 2`, not 4.** Benchmarked on the build machine at 4096²:

| Compression level | Time       | Output          |
| ----------------- | ---------- | --------------- |
| 1                 | 17.2 s     | 3,327,700 B     |
| **2**             | **27.7 s** | **3,295,496 B** |
| 4                 | 78.2 s     | 3,295,896 B     |

Level 4 is **2.8× slower than level 2 and produces a file 400 bytes larger**.
Level 2 is the knee of the curve, and the default was leaving minutes per texture
on the floor for nothing.

**2. Normal maps are plain RGB UASTC, without `--normal-mode`.** `--normal-mode`
repacks to two channels as (RGB = X, A = Y). Three's `KTX2Loader` transcodes
every Basis payload to an RGBA format and never to `RG11_EAC` or `RGTC2` — the
only formats `WebGLPrograms.isPackedRGFormat` recognises — so
`USE_PACKED_NORMALMAP` never fires, three samples `normalMap.xyz`, and a packed
map arrives as (X, X, X). Not subtly wrong: comprehensively wrong. RGB UASTC
with normal-tuned RDO (`--uastc-rdo-l 0.5`) is the encoding three can actually
consume.

### Orientation

Every output is written bottom-left origin (`--convert-texcoord-origin
bottom-left`, `KTXorientation: ru`). `KTX2Loader` produces a `CompressedTexture`,
which forces `flipY = false`, so the flip has to be baked into the bytes. Doing
so makes a KTX2 a drop-in replacement for the source JPEG loaded through
`TextureLoader`, and keeps a normal map's green channel pointing the way the
albedo beside it expects.

### Environments

HDRIs become half-float KTX2 plus a `<id>.sh9.json` carrying nine
spherical-harmonic irradiance coefficients. On mobile the runtime uses the SH9
path rather than PMREM: **27 floats already present in the manifest, versus a
~12 MB cubemap chain and its build cost.**

### The skip cache is the point

Encoding is expensive and profoundly repetitive — a 4096² albedo to ETC1S is
~28 seconds, and nothing about it changes between runs unless the source bytes
or the encoder settings did. Every output is therefore keyed by

```
sha256( srcSha256 | outPath | JSON(encodeOptions) | TOOL_VERSION | ktx version )
```

and a hit that still matches on disk (size + mtime) is reused untouched.

- Cold build of the mobile tier: **~6 minutes**.
- Warm re-run: **sub-second**, ~0.6 s — a pure no-op.
- Change one encoder flag: exactly the outputs that flag feeds are invalidated,
  and nothing else.

**Concurrency is 2 by default.** `ktx` is internally multi-threaded and already
saturates ~2.4 of the 4 cores available here, so a wider pool mostly steals
cache and memory bandwidth from the encode already running.

### What comes out

**153 KTX2 files**, each validated with `ktx2check` and re-parsed with
`ktx-parse`, plus 39 model GLBs and 14 generated character GLBs.

| Tier     | Outputs | Size                    | Coverage                          |
| -------- | ------- | ----------------------- | --------------------------------- |
| `mobile` | 166     | 90,510,274 B (86.3 MiB) | complete                          |
| `high`   | 13      | 48,003,900 B (45.8 MiB) | 4 environments + 3 materials only |
| `ultra`  | 13      | 57,114,501 B (54.5 MiB) | 4 environments + 3 materials only |

Only the mobile tier is currently built out. `high` and `ultra` have been run
far enough to validate the ladder — four environments and three materials each —
and no models at all. Building them is `npm run assets:process -- --tier high`;
nothing in the pipeline stands in the way, the time simply has not been spent.

The mobile tier — the one that ships in the APK — breaks down as:

|                        | Outputs | Size         |
| ---------------------- | ------- | ------------ |
| Material textures      | 123     | 52.4 MiB     |
| HDRI environments      | 4       | 9.7 MiB      |
| **Texture data total** | **127** | **62.1 MiB** |
| Models                 | 39      | 24.2 MiB     |
| **Total**              | **166** | **86.3 MiB** |

So: **62 MB of textures and 24 MB of models** for the whole city, against 1.65
GiB of source — a **19.6× reduction**.

## Stage 4 — runtime

The game loads exactly one file first: `public/assets/assets.runtime.json`. It
carries, per entry, the attribution block, the source sha256, and one `outputs[]`
row per tier with path, bytes, sha256 and dimensions — plus the baked SH9
coefficients for every environment and a `pipeline` block recording the encoder
version and the four gotchas a consumer must honour (ARM channel binding,
normal-map format, environment filtering, the SH9-over-PMREM advice).

Vite serves `public/` at the web root, so a processed file at
`public/assets/tex/foo/albedo.mobile.ktx2` is fetched as
`/assets/tex/foo/albedo.mobile.ktx2`.

For the APK, `scripts/build-apk.ts` prunes every non-mobile tier out of the
Capacitor copy before Gradle runs. Without that step the APK is ~296 MB — over
Google Play's base limit, and full of assets a phone would never load.

## Regenerating the attribution

`ATTRIBUTION.md` is generated from the manifests and the lockfile, never written
by hand:

```bash
npx tsx tools/attribution.ts           # regenerate
npx tsx tools/attribution.ts --check   # CI gate: fail if out of date
```

It refuses to emit the file if any entry lacks an author or a licence, if any
asset carries a licence the project cannot ship, or if the
zero-third-party-character-assets assertion stops holding.

## Known issue

`loadSourceManifests()` globs every `tools/manifest/*.json` and validates each
against the third-party source-entry schema. `characters.json` is deliberately a
different shape, so the load currently aborts:

- `assets:fetch` exits 1 and downloads nothing.
- `assets:process` still builds textures and environments (they read the already
  resolved `assets/source/manifest.resolved.json`), but the model stage fails,
  because `tools/process-models.ts` calls the same loader.

`MANIFEST_FILES` already exists in `tools/lib/manifest.ts` and lists exactly the
three source manifests; restricting the loader to it — or moving
`characters.json` elsewhere — resolves this.
